# استقرار نسخه تحویلی دبیرستان شهید بهشتی

## خروجی مورد انتظار

پروفایل `shahid-beheshti` فقط موارد زیر را در یک پایگاه داده تازه ایجاد می‌کند:

- یک مدرسه: دبیرستان شهید بهشتی
- یک حساب `ADMIN` با مشخصات تعیین‌شده توسط مالک سامانه
- یک حساب `VICE_PRINCIPAL` به نام حمید باقری
- snapshot کامل‌تر سال ۱۴۰۵–۱۴۰۶ شامل ۱۰ کلاس، ۲۱ دبیر، ۳۴ درس، ۱۳۱ قاعده curriculum، ۱۴۶ نیاز، ۳۵۰ ساعت و ۲۲۲ جلسه
- حمید باقری به‌عنوان معاون و دبیر فارسی/نگارش با ۶ ساعت تخصیص (`فارسی ۴ + نگارش ۲`) و حضور شنبه/چهارشنبه مطابق دادهٔ جاری

نسخه عادی `npm run db:setup` همچنان برای توسعه محلی است و سه مدرسه نمایشی می‌سازد. آن را روی دیتابیس تحویلی اجرا نکنید.

## انتخاب سرویس

برای استقرار یک‌جای رابط و API، Vercel با این پروژه Next.js سازگار است. دیتابیس PostgreSQL باید پایدار و بیرون از فایل‌سیستم اجرای Vercel باشد؛ می‌توان یک PostgreSQL مدیریت‌شده از Marketplace مانند Neon یا Supabase متصل کرد. Netlify نیز ممکن است، اما مسیر مستند و کم‌اصطکاک این پروژه Vercel است.

## متغیرهای محیطی

این مقادیر را در Production Environment پروژه تنظیم کنید:

```dotenv
DATABASE_URL=postgresql://...
DATABASE_POOL_MAX=1
SESSION_COOKIE_NAME=school_panel_session
```

مقادیر زیر فقط هنگام bootstrap لازم‌اند و باید رمزهای قوی و متفاوت داشته باشند:

```dotenv
SEED_ADMIN_EMAIL=owner@example.com
SEED_ADMIN_NAME=مدیر سامانه
SEED_ADMIN_PASSWORD=یک-رمز-قوی-حداقل-۱۲-نویسه
SEED_VICE_PRINCIPAL_EMAIL=hamid.bagheri@example.com
SEED_VICE_PRINCIPAL_PASSWORD=یک-رمز-قوی-و-متفاوت-حداقل-۱۲-نویسه
```

رمزها را در فایل commitشده، مستند تحویل، خروجی فرمان یا کانال عمومی قرار ندهید.

## مراحل استقرار روی Vercel

1. مخزن را در Vercel Import کنید و Framework Preset را روی Next.js نگه دارید.
2. یک PostgreSQL تازه و خالی بسازید و `DATABASE_URL` آن را در محیط Production قرار دهید.
3. متغیرهای بالا را در محیط امن ترمینال/CI قرار دهید و فقط یک بار اجرا کنید:

   ```bash
   npm ci
   npm run db:setup:delivery
   ```

4. برنامه را از رابط Vercel یا با `vercel --prod` مستقر کنید. migration و seed نباید به فرمان build متصل شوند.
5. پس از bootstrap، متغیرهای `SEED_*_PASSWORD` را از محیط Vercel حذف کنید؛ اجرای عادی برنامه به آن‌ها نیاز ندارد.
6. با هر دو حساب وارد شوید و مطمئن شوید انتخاب مدرسه فقط «دبیرستان شهید بهشتی» را نشان می‌دهد.
7. پیش‌بررسی را باز کنید؛ داده تحویلی فعلی باید بدون خطای مسدودکننده آماده تولید برنامه باشد.
8. پیش از تحویل، از دیتابیس نسخه پشتیبان بگیرید.

## کنترل‌های امنیتی seed

- seed تحویلی بدون ایمیل و رمزهای صریح اجرا نمی‌شود.
- رمز هر حساب باید حداقل ۱۲ نویسه باشد و دو رمز باید متفاوت باشند.
- اگر مدرسه یا کاربر اضافه در دیتابیس وجود داشته باشد، seed متوقف می‌شود و چیزی را حذف نمی‌کند.
- رمزها در خروجی seed چاپ نمی‌شوند.
- این seed برای bootstrap یک‌باره دیتابیس تازه است. پس از شروع ویرایش معاون، آن را دوباره اجرا نکنید؛ فقط migrationهای جدید را با `npm run db:migrate` اعمال کنید.

## بررسی قبل از تحویل

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

سپس ورود مدیر و معاون، محدود بودن هر دو به مدرسه شهید بهشتی، نمایش داده‌های سال ۱۴۰۵–۱۴۰۶، و امکان ذخیره مشخصات و حضور دبیر را روی نشانی نهایی بررسی کنید.
