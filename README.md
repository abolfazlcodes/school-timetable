# مدرسه‌یار

پنل فارسی و RTL برای مدیریت و تولید قطعی برنامه هفتگی مدارس.

## اجرای محلی

پیش‌نیازها: Node.js 22، npm و Docker.

```bash
cp .env.example .env.local
npm install
npm run db:setup
npm run dev
```

سپس `http://localhost:3000` را باز کنید.

`npm run dev` در اتصال محلی، PostgreSQL پروژه را با Docker Compose به‌صورت خودکار اجرا و تا آماده‌شدن آن صبر می‌کند. برای اجرای دستی دیتابیس نیز می‌توان `npm run db:up` را اجرا کرد. اتصال‌های غیرمحلی مانند Neon تغییری نمی‌کنند.

حساب‌های نمایشی پس از seed:

- مدیر: `admin@madreseyar.ir` / `Demo123!`
- معاون: `moaven@madreseyar.ir` / `Demo123!`

حساب مدیر به سه مدرسه دسترسی دارد: «دبیرستان فرزانگان»، «دبیرستان دانا» و «دبیرستان شهید بهشتی». شهید بهشتی با snapshot کامل‌تر سال ۱۴۰۵–۱۴۰۶ شامل ۱۰ کلاس، ۲۱ دبیر، ۳۴ درس و ۳۴۹ ساعت آموزشی seed می‌شود. تخصیص قطعی کلاس/درس/دبیر از جدول نهایی معاون وارد seed نشده است تا حل‌گر برنامه را از داده خام بسازد. دو مدرسه دیگر fixture توسعه‌ای کوچک‌تر هستند.

در شهید بهشتی، روزهای اعلام‌شده در سند به‌عنوان `AVAILABLE` و سایر روزها به‌عنوان `UNAVAILABLE` ثبت می‌شوند؛ اصلاح مستقیم روح‌الله احمدی، علی اسدی و علی رضیئ نیز بر تصویر اولویت دارد. در fixtureهای قدیمی دو مدرسه توسعه‌ای، روزهای سند همچنان ترجیح نرم هستند.

داده شهید بهشتی از نظر ۳۴۹ ساعت نیاز و پوشش دبیران متوازن است. زنگ‌های اول تا سوم دو واحد و زنگ چهارم یک واحد آموزشی دارند؛ قواعد جلسه از curriculum همان مدرسه خوانده می‌شوند، فقط عربی دوازدهم تجربی به‌صورت `۱+۱` ثبت شده و سایر عربی‌ها یک جلسه `[۲]` هستند. preflight بدون خطای مسدودکننده عبور می‌کند و آزمون حل‌گر، برنامه معتبر را مستقیماً از همین داده خام تولید می‌کند. جزئیات در [گزارش بازبینی داده کامل‌تر](docs/SHAHID-BEHESHTI-COMPLETE-DATA-REVIEW.md) ثبت شده است.

## جریان نمونه برنامه

از «برنامه‌ریزی» ساختار، دروس، دبیران و حضور را بررسی کنید؛ در گام «بررسی اطلاعات» خطاهای مسدودکننده را رفع و در گام بعد برنامه را تولید کنید. یکی از گزینه‌ها را برای اصلاح به workspace ببرید، تغییرها را اعتبارسنجی کنید و در گام «انتشار» نسخه جاری را منتشر کنید. تاریخچه، fork نسخه قبلی و خروجی PDF/Excel/چاپ همگی در «برنامه هفتگی» قرار دارند.

## کنترل کیفیت

```bash
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run benchmark:scheduling
npm run build
```

`npm run db:setup` تکرارپذیر است و می‌توان آن را برای اعمال migrationهای جدید و به‌روزرسانی idempotent داده نمایشی دوباره اجرا کرد. جزئیات معماری در پوشه `docs` و وضعیت پیاده‌سازی در `docs/PHASE-1-CHECKLIST.md` قرار دارد.

## نسخه تحویلی شهید بهشتی

برای ساخت نسخه واقعی آزمایشی از seed عادی استفاده نکنید. پروفایل تحویلی فقط «دبیرستان شهید بهشتی»، حساب مدیر، حساب معاون حمید باقری و داده مرجع فعلی را روی یک PostgreSQL تازه ایجاد می‌کند:

```bash
npm run db:setup:delivery
```

این فرمان به متغیرهای امن `SEED_ADMIN_EMAIL`، `SEED_ADMIN_PASSWORD`، `SEED_VICE_PRINCIPAL_EMAIL` و `SEED_VICE_PRINCIPAL_PASSWORD` نیاز دارد و نباید پس از شروع ویرایش داده‌های واقعی دوباره اجرا شود. جزئیات در [راهنمای استقرار](docs/DEPLOYMENT.md) و متن آماده تحویل در [راهنمای معاون](docs/VICE-PRINCIPAL-TEST-GUIDE.md) آمده است.
